StudyMode: technical plan

This is how StudyMode gets built: two small parts on your laptop that turn a long PDF into study rounds, one chunk at a time.

How it works, in plain language

The page you see is built with plain HTML, CSS and JavaScript, the three languages every browser understands, with no extra toolkit. It reads your PDF with PDF.js and cuts the text into chunks of about 600–800 words.

A small helper program (a server) hands the page to your browser and holds your secret Claude API key. The page sends it one chunk at a time. The helper asks Claude for key points, flashcards and a quiz, then hands them back. The key never reaches the page.

Nothing is saved. It all lives in one state object in the page's memory until you close the tab. Click a box below to see what it does.

What the helper sends back for one chunk

Claude is required to reply in exactly this shape (called structured outputs), so the page always knows where the key points, cards and questions are.

{
  "keyPoints": ["Plants use **photosynthesis** to turn light into food.", ...],   // 3–5
  "flashcards": [{ "front": "What is chlorophyll?", "back": "The green pigment..." }, ...],   // 10
  "quiz": [{ "question": "...", "options": ["…","…","…","…"],
             "correctIndex": 1, "explanation": "..." }, ...]   // 5
}

Claude always makes 10 cards. Your 1–10 pick just chooses how many to show, so changing it is instant and costs nothing extra.

All of it is held in the state object in app.js. "Gone" is on purpose: saving was cut in scope.md.

How to run it and record the demo

  1. Install Node.js (current LTS). In the Claude Console (platform.claude.com), add some prepaid credit, make an API key, and set a monthly spending limit. Claude Pro doesn't cover API use.
  2. In the project folder, run npm install.
  3. Copy .env.example to .env and paste your key after ANTHROPIC_API_KEY=. Never paste the key into chat.
  4. Run npm start, then open http://localhost:3000. After editing page files, just refresh the browser.

Demo video: Get started → upload a 3+ page PDF → summary with highlights → make one card → pick 5 cards and flip a couple → quiz with right and wrong feedback → score → next chunk appears. You'll submit this video plus the public GitHub repo. Hosting is optional and decided in 6-ship.

Where it could break, and what you'll see

  • Unusable file (not a PDF, or a scanned PDF): "We couldn't read text from this file. Try another PDF, or paste your text below."
  • Claude call fails (missing key, spending limit reached, no internet): "We couldn't prepare this chunk…" with a Try again button. Your score so far is kept.
  • Slow reply (10–30 seconds): the loading ring keeps spinning with "This can take a few seconds…".

What was kept simple

  • One Claude request per chunk returns the key points, 10 cards and the quiz together.
  • Each chunk is prepared when you reach it, so you only pay for what you study. There's a short wait on each Next chunk.
  • One "current screen" value instead of separate web addresses. The browser back button won't move between screens.
  • Plain HTML/CSS/JavaScript instead of React: no build step, one command to start. The page is redrawn whole on every change, which is simple and fast enough here.
  • The helper also serves the page: one program, one port.
  • Nothing saved, and it runs locally.

Nothing is faked: every summary, card and question comes from Claude reading your real chunk.

Can you switch to React later?

Yes. It's a rewrite of the screen files, not a start-over. The code is split so that most of it carries over:

PartIf you switch to React
Helper server, Claude requestUnchanged
readPdf.js, chunkText.js, api.js, styles.cssUnchanged
state object + actionsBecome React state and event handlers, with the same names
screens/ and components/ filesEach becomes one React component with the same job

Roughly a few hours of guided work once the app runs. It's best done after you submit.

Decisions

  • Run locally; decide on hosting later your choice
  • Page + small helper server holding the key recommended, you agreed
  • Plain HTML/CSS/JavaScript, to ship fast (replaces React) your choice
  • Chunks of about 600–800 words, split at paragraph breaks recommended, you agreed
  • Key points with highlights, never raw text your request
  • Dark blues, light background, clean font your choice
  • Express serving the page, state + render pattern, 10 cards per request, **term** highlights, Front/Back own card build details, adjustable

Claude model: Opus 5.5 at low effort, about 5¢ per chunk your choice
