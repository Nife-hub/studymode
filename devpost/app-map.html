StudyMode: App Map

A one-page guide to how your app fits together and where to make changes. It's a snapshot of commit b143b91, so it may drift as the code changes.

What it is, in two parts

The page you see (public/) is plain HTML, CSS and JavaScript. It reads your PDF in the browser, cuts the text into chunks of about 600–800 words, and shows the screens. Everything you're doing right now lives in one object called state in public/app.js. Each change to state goes through a small action function and then redraws the page with render().

The helper server (server/) hands the page to your browser and keeps your Claude API key private. For each chunk you study, it asks Claude for key points, 10 flashcards and a 5-question quiz.

One action, end to end: upload a PDF → see key points

Reference route: three stops to read

You didn't take this tour during the build. You can follow it yourself any time: open each file and search for the name in code.

  1. public/screens/home.js, search for startFromPdf. Choosing a file in the upload box calls this action. The screen itself never changes data; it just asks app.js to.
  2. public/app.js, search for startFromPdf, then loadRound. startFromPdf pulls the text out with readPdf, cuts it with chunkText, and loadRound shows the loading ring while it fetches chunk 1. When the reply arrives, it puts it in state.round and redraws, so the Study Screen appears.
  3. server/studyRound.js, search for makeStudyRound. This is the only place that talks to Claude. SYSTEM_PROMPT tells Claude what to write, and checkCounts makes sure there are 3–5 key points, 10 flashcards and 5 quiz questions before anything reaches the page.

A practice to reuse: describe the feeling, keep design decisions in one place

Every look-and-feel change in this build started as a plain description from trying the running app: "too bright for a long session", then "too bland, make it friendly and casual". Each one landed in the same place, the color and font variables at the top of public/styles.css. spec.md › Look and Feel was updated each time so the documents and the app agree. Before shipping, every text color was checked against the 4.5:1 contrast standard in both modes.

On your next project, have the agent set up design variables early, then react to the real thing in plain words ("too bright", "too busy"). A whole-app change becomes a few edits in one file, and you can tell the agent exactly where to look.

Related: test a guess before acting on it

When a 100-page PDF failed, the first guess was "it's too big". Instead of changing code, the agent made a 95-page test PDF and ran it through public/lib/readPdf.js. It worked (67 chunks), which ruled size out and pointed to a scanned PDF. Asking an agent to check a guess first is often faster than fixing the wrong thing.

Run it again

In the studymode folder: npm start, then open http://localhost:3000. Your key lives in .env, which git ignores. A PDF known to work is in sample/sample-notes.pdf.
